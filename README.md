# open-table-agent

MCP server and a minimal patch set that give AI agents full access to a self-hosted open-source Teable (Community Edition).

## Build shim

The host has podman 4.3.1 / buildah 1.28, which rejects `COPY --link` (used by the upstream Teable Dockerfile). `e2e/bin/podman` (set as `OTA_PODMAN`) renders a derived Containerfile into `.work/build-shim/` with `--link` removed from COPY/ADD lines (`e2e/build_shim.py`) and builds that one. `--link` only affects layer caching, not the image. The same rendering prefixes upstream's `RUN pnpm fetch` with a pnpm-store seed of `xlsx-0.20.3.tgz` (cdn.sheetjs.com is unreachable): `python3 e2e/vendor_xlsx.py` fetches it via the download broker, verifies it against the lockfile sha512 and prints the `--podman-arg=--volume=...:/ota-vendor:ro` to pass to `sync-upstream.py --build`. The upstream `post-builder`/`runner` stages `apt-get` from deb.debian.org (unreachable): `e2e/apt_proxy.py` is a broker-backed local apt proxy (every Release/Packages/.deb fetched via `hermes-download`, checked against the signed Release/Packages sha256, cached in `.work/apt-cache/`). Build-only values (`PRISMA_ENGINES_MIRROR` pointing at the local broker-verified engine mirror, so prisma's own postinstall/generate install query + schema engines into node_modules exactly as upstream; node-gyp `npm_config_nodedir`, apt's `APT_CONFIG` pointing at the local proxy; no `http_proxy`, so npm/node downloads stay upstream-identical) are passed as `--build-arg`, never `--env`, so they are not baked into the image's `Config.Env`: the shim declares `ARG` for them after every `FROM` (ARG scope is per stage). `e2e/node_headers.py` fetches `node-v<ver>-headers.tar.gz` via the broker (verified against a sha256 pinned in `e2e/node_headers.py`, taken from nodejs.org's published `SHASUMS256.txt` for that version; a freshly fetched `SHASUMS256.txt` is cross-checked against the pin, `--unverified` since only a detached GPG signature exists; bumping the node version needs a new pin) and mounts it read-only for node-gyp (no nodejs.org access, so `cpu-features` builds as upstream). The single D2 build command is `python3 e2e/apt_proxy.py build -- [sync-upstream.py args]` (fetches Prisma engines + xlsx + node headers, runs proxy and build in one process). The upstream Dockerfile is never edited. `upstream.lock.json` is rewritten wholesale by `scripts/sync-upstream.py`, so the shim is documented here only.
